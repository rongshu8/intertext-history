## 零、验证过的运行环境

代码在这些组合上真实装过并跑通：

| 项 | 值 |
|---|---|
| PHP | **7.4.33**（代码兼容 7.4 ~ 8.4） |
| 数据库 | **MySQL 5.5.62** ⚠️ 见下方「MySQL 5.5 限制」 |
| 字符集 | utf8mb4（连接锁 `utf8mb4_unicode_ci`） |
| 持久连接 | 开启（`PDO::ATTR_PERSISTENT`） |
| Web 服务器 | Apache + 宝塔面板 |

选MySQL 5.5 作为兼容底线是刻意的：能跑在5.5 上，就一定能跑在 8.x 上（反之不然）。 |

### ⚠️ MySQL 5.5 的三个硬限制（踩过坑，勿改回）

1. **不支持 `DATETIME DEFAULT CURRENT_TIMESTAMP`**（5.6+ 才有）
   → 所有时间戳列都是 `DATETIME NULL`，由应用层用 `SQL_NOW` 常量显式写入。

2. **索引键长上限 767 字节**（Antelope + `innodb_large_prefix=0`）
   → utf8mb4 下唯一索引列不得超过 **191 字符**。当前最长的是 `users.username VARCHAR(48)`（192 字节），安全。
   → `Schema::createIndex()` 会从 DDL 反查列宽并在超限时抛错，不会等到建索引才报 1071。

3. **`sql_mode` 默认不含 `STRICT_TRANS_TABLES`**
   → 连接时用 `CONCAT_WS` **追加**该值（不是覆盖！），让越界值直接报错而非静默截断
     —— 静默截断会写坏数据且难以察觉。详见第四节。

**时间戳拼接的正确写法**（`php -l` 查不出写错的版本）：

```php
// 正确：引号闭合后再拼接
'INSERT INTO t (a, created_at) VALUES (?, ' . SQL_NOW . ')'

// 错误：拼接符落在单引号串内，SQL_NOW 变字面量 → 1292 Invalid datetime
'INSERT INTO t (a, created_at) VALUES (?, " . SQL_NOW . ")'
```

改完 SQL 后务必跑一次 `python tools/check_sql_quotes.py`（用 PHP tokenizer 判定）。

## 一、快速开始

### 环境要求

| 项 | 要求 |
|---|---|
| PHP | 7.4+（线上为 7.4.33，**勿用 8.x 语法**） |
| 扩展 | `pdo` + `pdo_mysql`（必需），`mbstring` / `json` / `session`（建议） |
| 数据库 | **MySQL 5.5 ~ 8.4** / MariaDB 10.x（不支持 SQLite） |
| Web 服务器 | Apache / Nginx / PHP 内置服务器均可 |

### 安装

1. **上传全部文件**到网站根目录（或子目录）。本目录需有**写权限**。

2. **浏览器访问你的域名根目录**，会自动跳到安装向导：

   ```
   http://你的域名/    →  302 → /install.php
   https://你的域名/   →  302 → /install.php
   ```

   **`http://` 与 `https://` 都可安装、可用，无差别。**

   然后：

   1. **填数据库信息** —— 地址、端口、库名、用户名、密码
      （本机数据库填 `127.0.0.1:3306`）。点「下一步」自动测连接
   2. **环境检测** —— 自动显示 PHP 版本、扩展、MySQL 版本、排序规则
   3. **点「开始安装」** —— 建表、导数据、写配置、上锁，一次完成

   **不需要手工编辑任何文件。** 安装器会在本目录生成 `config.local.php`。

   **库不存在也没关系 —— 安装器会自己建**（`CREATE DATABASE`，字符集自动
   `utf8mb4`），并先建一张临时表验证权限再删掉。任一步失败都会明确说明原因。

   装完的完成页会给你两个大按钮：**进入前台** / **进入后台**，
   并显示管理员 `admin` 的随机密码（**只显示这一次**）。

   > ⚠️ 自动建库需要 MySQL 账号有全局 `CREATE` 权限。宝塔与多数虚拟主机
   > 默认只给「单库」权限，此时自动建库会失败并提示你 ——
   > 那时在面板「数据库」点「添加数据库」（字符集 `utf8mb4`），
   > 把库名回填到表单即可。
   >
   > 唯一前置条件：**站点根目录要可写** —— 安装器要在那里写 `config.local.php`。
   > 权限不够会明确提示，那时改用下面的「手工配置」。

### 手工配置（可选）

若环境不允许安装器写文件，可自己建 `config.local.php`：

```php
return [
    'db' => [
        'driver' => 'mysql',
        'host'   => '127.0.0.1',
        'port'   => 3306,
        'name'   => 'history_timeline',
        'user'   => 'your_user',
        'pass'   => 'your_password',
    ],
];
```

放好后直接访问 `/install.php` 会跳过第一步，从环境检测开始。

### 管理员账号

安装时会自动创建管理员：

```
用户名：admin
密码：安装时随机生成，在安装完成页显示一次
```

密码**不写死在代码或文档里**，每次安装都不同。
完成页只显示这一次，刷新即失效；丢失后无法找回。
**安装后第一件事：登录后台 → 账户 → 改成一个自己的密码。**

### 安装锁

安装完成时写入 `data/install.lock`，此后 `install.php` **只读**：
不渲染任何表单，伪造 POST 也返回 403。

CSRF 防的是跨站触发，不防直接访问 —— 而令牌就印在页面上。
所以这道保护不能靠令牌，必须靠"根本没有可提交的东西"。

重装需服务器权限：FTP 删 `data/install.lock`，或 `php install.php --force`。

## 三、数据模型

```
dynasties（中国历史分期）
    │
    ├── cn_events（中国历史节点）──── relations（中外联动）──── world_events（世界大事）
    │        ↑                                                      ↑
    │   时间主轴上的锚点                                        按 year 独立存储
    │   （页面入口）                                            （节点页按 ±N 年窗口检索）
    │
    └── categories / regions / relation_types（字典表）
```

### 关键设计：带符号年份

所有年份用**带符号整数**存储，公元前 221 年记为 `-221`，公元 2026 年记为 `2026`。

好处是 SQL 里可以直接做数值区间比较，不需要在查询时区分公元/公元前两套逻辑：

```sql
-- 命中窗口内的世界大事（单点事件 + 区间事件都要覆盖）
WHERE (
    (year_end IS NULL AND year BETWEEN :lo AND :hi)
 OR (year_end IS NOT NULL AND year <= :hi AND year_end >= :lo)
)
```

前台展示时由 `fmt_year()` / `fmt_year_range()` 负责转换成「公元前 221 年」这样的文本。

### 核心查询

```php
// 取某节点 ±5 年内的世界大事
world_events_near(int $year, ?int $yearEnd, ['window' => 5, 'limit' => 120]);

// 某节点已配置的中外联动（含世界事件详情）
relations_of_cn(int $cnEventId);

// 某条世界大事反向关联哪些中国节点
cn_events_of_world(int $worldEventId);
```

## 四、版本兼容

**只支持 MySQL**（5.5 ~ 8.4 / MariaDB 10.x）。SQLite 支持已于 2026-10-05 移除 ——
多用户投稿 + 管理员审核是并发写场景，SQLite 的整库写锁会成为瓶颈。

### 版本差异与本项目的处理

| 事项 | MySQL 5.5 | MySQL 8.x | 本项目做法 |
|---|---|---|---|
| `DATETIME DEFAULT CURRENT_TIMESTAMP` | ✗ 不支持 | ✓ | 时间列一律 `DATETIME NULL`，由应用层用 `SQL_NOW` 显式写入（行为两边一致） |
| utf8mb4 默认排序规则 | `utf8mb4_general_ci` | `utf8mb4_0900_ai_ci` | **建表显式锁 `COLLATE=utf8mb4_unicode_ci`**（5.5~8.4 唯一安全交集） |
| `sql_mode` 默认值 | 无 STRICT | 含 STRICT + ONLY_FULL_GROUP_BY 等 | 连接时**追加** `STRICT_TRANS_TABLES`，不覆盖服务端原有设置 |
| 索引键长上限 | 767 字节 | 3072 字节 | 唯一索引列 ≤191 字符（`Schema::createIndex()` 会提前拦截并报错） |
| `innodb_large_prefix` | OFF | 已移除该变量 | 代码自动探测；8.x 上按 3072 字节处理 |

### 两个不要改的写法

**1. `sql_mode` 必须追加，不能覆盖**

```php
// ✗ 覆盖式：会把服务端原有的 NO_ZERO_DATE / ONLY_FULL_GROUP_BY 全丢掉
SET SESSION sql_mode = 'STRICT_ALL_TABLES,NO_ENGINE_SUBSTITUTION'

// ✓ 追加式（见 inc/db.php 的 initSession）
SET SESSION sql_mode = CONCAT_WS(',', NULLIF(@@SESSION.sql_mode, ''),
                                'STRICT_TRANS_TABLES', 'NO_ENGINE_SUBSTITUTION')
```

覆盖式写法在 5.5 上看不出问题，但在 8.0 上等于**主动关闭了它精心设计的默认防护**。

**2. 时间戳拼接必须让引号先闭合**

```php
// 正确
'INSERT INTO t (a, created_at) VALUES (?, ' . SQL_NOW . ')'

// 错误：拼接符落在单引号串内，SQL_NOW 变字面量 → 1292 Invalid datetime
'INSERT INTO t (a, created_at) VALUES (?, " . SQL_NOW . ")'
```

`php -l` 对两种都报「无语法错误」。改完任何 INSERT/UPDATE 跑一次
`python tools/check_sql_quotes.py`（用 PHP tokenizer 判定）。

### 内容口径

- 事件年代与人物生卒采用**通说**。
- 早期断代（尤其夏商周）存在学术分歧，取主流说法。
- **中外并列仅表示大致同时期**，不代表存在因果关系。真正有因果或结构性呼应的节点已单独用「联动」标出（如「怛罗斯之战 → 造纸术西传」「工业革命 → 鸦片战争」）。
- 涉及近现代史的表述，以中国现行中学历史教材的通行口径为基础。
- 种子内容由 AI 生成后人工整理，细节与年代可能存在错误，**请以权威史料为准**。

## 七、安全说明

已实现的防护：

| 项 | 实现 |
|---|---|
| SQL 注入 | 全部查询走 PDO 预处理；`LIMIT` / `OFFSET` 强制 `(int)` 转换；动态表名过白名单 |
| XSS | 所有输出经 `h()`（`htmlspecialchars` + `ENT_QUOTES`） |
| CSRF | 所有 POST 表单带 `_csrf` 令牌，`csrf_check()` 校验（含 install / 迁移工具） |
| 会话固定 | 登录后 `session_regenerate_id(true)` |
| 密码存储 | `password_hash()` / `password_verify()`，登录失败用假 hash 防用户名枚举 |
| 暴力破解 | 登录 5 次/5 分钟、注册 10 次/1 小时限流，桶按「用户名+IP」组合 |
| 重名竞态 | `users.username` 加唯一索引，数据库层兜底（不只靠应用层 SELECT） |
| Cookie 安全 | `httponly` + `samesite=Lax` + HTTPS 下 `secure` |
| 响应头 | `X-Frame-Options: SAMEORIGIN`（防点击劫持）、`X-Content-Type-Options`、`Referrer-Policy`、`Permissions-Policy` |
| 文件暴露 | `.htaccess` 屏蔽 `config.php`、`config.local.php`、`data/`、`inc/`、`tools/`、备份文件 |
| 目录列举 | `Options -Indexes` |

> **CSP 未启用**：页面大量使用内联样式与内联脚本（时间轴交互、confirm 确认框），
> 贸然上 strict CSP 会直接白屏。需要时先做 nonce 改造。

**上线前必做**：

1. 删除 `install.php`（能建表、清库、导数据）
2. 修改 admin 默认密码
3. 确认 `data/` 目录不可被直接下载（`.htaccess` 已配，Nginx 需手工加规则）
4. 生产环境把 `config.local.php` 里的 `site.debug` 设为 `false`（默认即是）

### Nginx 环境

Nginx 不读 `.htaccess`，需要在站点配置里加：

```nginx
location ~ ^/(data|inc|tools|cache)/ { deny all; }   # data/ 只放种子 PHP，必须禁止直接访问
location ~ \.(sqlite|sqlite-wal|sqlite-shm|sql|bak|old|log|ini|md)$ { deny all; }
location = /config.php  { include fastcgi_params; fastcgi_pass unix:/tmp/php-fpm.sock; }
location = /config.local.php { deny all; }
```

### 移动端两项专门改造

**1. 筛选面板折叠（≤900px）**

25 个朝代 + 10 个主题的 chip 平铺会占掉两三屏，把时间轴这个主体全推到折叠线以下。
窄屏收成一行 sticky 按钮，点开才展开面板：

- 按钮上显示**当前已选摘要**（如「唐 · 战争军事」）与已选条件数角标
- 选中 chip 后面板自动收起，让用户立刻看到筛选结果
- 从窄屏拉宽到桌面时，面板自动复位为展开态
- 桌面端按钮隐藏、面板恒开 —— 行为由 CSS media query 保证，不依赖 JS

**2. 时间轴重排与卡片减重（≤900px）**

原移动端布局的三个错位根因（`tools/verify_mobile_timeline.py` 实测确认）：

| 问题 | 根因 | 修法 |
|---|---|---|
| 圆点与卡片错位 | `.tl-cards.left` 与 `.tl-cards.right` 都是 `grid-row: 1`，叠在同一网格单元 | 窄屏改为 `left: row 1` / `right: row 2` |
| 年份飘在半空 | 年份是独立列且竖排，`max-height: 190px` 被截断 | **年份移入卡片内**（`.tl-year-in`），独立年份列整体隐藏 |
| 单行 300–500px 太高 | 每行 1 中国节点 + 4 世界大事 + 摘要正文 | 世界大事**服务端按 UA 减到 2 条**，窄屏隐藏摘要正文与地区标签 |

> 「年份移入卡片」是根治：不再是两个独立网格项对齐，而是一个元素。
> 桌面端用 CSS 隐藏卡内那份、走主轴那份，两份互斥显示。

结果：单行高度 **306px → 177px（-42%）**，年份与标题零重叠，中国节点卡 8/8 行可见。

### 已处理的移动端陷阱

- **iOS 输入框自动放大**：字号 <16px 时 iOS Safari 会自动放大整页 → 触屏尺寸下强制 16px
- **触控目标过小**：世界大事列表 40 个标题链接原仅 20px 高 → 用 `padding` 扩大热区 + 负 `margin` 抵消，视觉排版不变
- **grid-row 重叠**：`left`/`right` 同为 `grid-row:1` 会让一侧卡片被压掉 —— 单列布局必须显式分配不同 row
- **图片撑破布局**：`img/video/svg` 统一 `max-width: 100%`
- **长 URL 溢出**：`overflow-wrap: break-word`
- **触屏 hover 粘住**：`@media (hover: none)` 下关闭 transition 与 hover 效果
- **键盘可达性**：`focus-visible` 统一焦点环

## 七之三、安装闸门（新增页必读）

**每个前台入口页 + `admin/login.php` 的第一行是 `install_gate.php`，
不是 `bootstrap.php`。**

```php
require_once __DIR__ . '/inc/install_gate.php';   // 未装 → 302 到 install.php
require __DIR__ . '/inc/bootstrap.php';
```

顺序不能反。原因很实在：`bootstrap` → `DB::pdo()` → `new PDO(...)`，
没配置数据库时抛 `PDOException`，全新用户打开首页看到的是 **HTTP 500 白屏**，
完全不知道「哦原来要先去装」。

`install_gate.php` 只做两次 `is_file()` —— 判 `config.local.php` 在不在，
**不连库**（连库就自己先挂了）。已装的站开销可忽略。

```
config.local.php 不存在  →  302 → /install.php（带 from 参数，装完可跳回）
config.local.php 存在    →  什么都不做，正常跑
```

`tools/smoke_pages.php` 的 `[4b]` 会检查这一条（含顺序），
`selftest_package.php` 的 `[1b]` 会在装前检查包里有没有漏。

### 站内新增页时的两条硬规则

1. **入口页第一行是 `install_gate.php`**，不是 `bootstrap.php`。
   忘了会得到一个"新页面在全新站上白屏"的 bug，而且本地测不出来。
2. **不要在闸门之后、`bootstrap` 之前用任何函数**（`q()` `h()` `cfg()` 都不行），
   那一刻它们都还没加载。

### `check_sql_quotes.py` 为什么必须存在

MySQL 5.5 不支持 `DATETIME DEFAULT CURRENT_TIMESTAMP`，时间戳必须由应用层拼接。
拼接写错时 PHP 语法完全合法，只有运行时才炸：

| 写法 | 结果 |
|---|---|
| `'... VALUES (?, ' . SQL_NOW . ')'` | ✓ 正确 |
| `'... VALUES (?, " . SQL_NOW . ")'` | ✗ 1292 Invalid datetime format |

`php -l` 对两种都报「无语法错误」。该脚本用 PHP 官方 `token_get_all()` 判定：
若字符串字面量的**内容里**含有 ` . SQL_NOW . `，说明拼接符落在串内，即为 bug。

> 历史教训：这个问题我用纯正则写了三版都误判/漏报，最后改用 tokenizer 才可靠。
> **不要试图用正则判断字符串边界**——嵌套引号、双引号插值会让正则彻底失准。

> `check_php.py` 是启发式检查，**不能替代 `php -l`**。
>
> ```bash
> for f in $(find . -name "*.php"); do php -l "$f"; done
> ```

### 索引语法的坑（已修复，勿回退）

`inc/schema.php` 的 `indexes()` 只返回**纯列定义**如 `'(year)'`，`createIndex()` 统一拼装成完整语句：

```
CREATE [UNIQUE] INDEX <name> [IF NOT EXISTS] ON <table> (<cols>)
```

- `UNIQUE` 必须在 `INDEX` **之前**，不能拼在索引名后面
- MySQL 不支持 `CREATE INDEX IF NOT EXISTS`，`createIndex()` 先查 `information_schema.statistics` 判存再执行

早期版本把 `UNIQUE` 拼在索引名后面，导致安装时报
`SQLSTATE[HY000]: General error: 1 near "UNIQUE": syntax error`。
改动 `indexes()` 或 `createIndex()` 后，务必重跑 `verify_index.py`。

## 九、常见问题

**Q：安装报 `near "UNIQUE": syntax error`？**
A：旧版本的索引拼接 bug（UNIQUE 位置错误）。更新 `inc/schema.php` 后重试。
本地可用 `php tools/dump_index_sql.php` 打印实际 SQL 核对。

**Q：安装报「检测到上次安装未完成」？**
A：表建好了但数据没导完。直接点页面上的「开始安装 / 修复」，
会自动清理残留后重新导入，不会重复报错。这是 `detect_state()` 检出的自愈路径。

**Q：页面提示「表不存在」？**
A：没跑安装器。访问 `install.php`，页面顶部会显示环境检测与具体错误。

**Q：想只修表结构不导数据？**
A：安装页（全新状态）底部有「仅建表与索引」按钮。


**Q：部署在子目录（如 `/history/`）会有问题吗？**
A：不会。`inc/layout_header.php` 的 `site_base()` 会自动识别路径前缀。
但 `.htaccess` 里的 `RedirectMatch` 规则需按实际路径调整。

**Q：节点页显示「同期暂无录入世界大事」？**
A：该节点时间窗口内确实没有对应记录。可以：
- 调大窗口（页面上有 ±1/±3/±5/±10/±20 切换）
- 在后台补录世界大事
- 这种情况在种子数据里是 0（100% 覆盖），但你删改数据后可能出现

**Q：时间轴节点顺序乱了？**
A：`cn_events` 按 `year ASC, month ASC, id ASC` 排序。检查是否有节点的 `year` 录错，
或 `month` 值异常。
